# 建筑实景图录：模型与照片并读

2026-10-15 第二轮扩展完成：太和殿11张、太庙前殿7张，共18张可再分发的实景照片（较首批新增14张）。入口位于各卷三维研究台之后；顶部与讲解面板提供“实景图录”链接。当前仅这两卷接入，不表示十三卷已补齐摄影资料。

## 阅读与操作

- 展示图保留完整画面，不以裁切后的特写冒充全貌。缩略图仅用于选图。
- 点击展开高清 WebP，100% 表示适合窗口；滑杆可到窗口宽度的四倍，并非相机原片的 400% 像素倍率。放大后滚动或触摸轻扫查看局部，原始 JPEG 另有链接。
- 弹层支持前后切图、适合窗口、Esc 关闭与焦点返回。手机使用浏览器原生滚动。
- 正文增加前后切图按钮，缩略图桌面四列、窄屏两列；高清弹层还支持左右方向键。照片按钮返回本建筑的对应讲解步骤；同一步骤的多张照片保留当前选图，屋角照片可进入转角局部；进入太和殿“藻井聚心”或太庙“金饰有载体”步骤时，图录同步选图。
- 图录通过独立模块加载，图片失败不会阻断三维初始化。

## 存储和当前可用性

沿用唐诗、宋词的 `readforfun-img.chunyangwen.com` 图片域名与现有 R2 配置，新增独立 `chinese-architecture/photos/<id>/<原片SHA256前16位>/` 前缀。18张照片各有原始 JPEG、高清 WebP、最长边不超过1600px的展示图和480px缩略图，共72个对象；本轮新增56个对象。按内容哈希寻址，`If-None-Match: *` 防止覆盖既有对象；命中已存在键时仍读回校验内容。没有更改 bucket 权限、DNS、WAF 或诗词资源。

本轮 R2 对象均已上传并经 S3 API 读回 SHA256 校验。**公开域名在当前网络返回 HTTP 403**，连原有唐诗图片也同样返回 403；不把 S3 成功写成公开 CDN 成功。页面优先请求 R2 地址，失败自动使用随页面交付的同尺寸 WebP 备用图。备用高清保留原始像素尺寸，原始 JPEG 的公开链接仍受域名访问状态影响。

`fallback/` 约 33.2 MiB，涵盖三种 WebP；原始 JPEG 留在 R2，仓库不重复保存。目录内的 `.gitignore` 对备用 WebP 作了限定例外，保证跨机器或静态发布时能携带。页面尚未提交或发布；bucket 图片已按本次用户建议上传。

## 后续项目复用步骤

1. 为每座建筑选“整体 + 构件上下文 + 关键细部”，先确认殿名、朝向、日期与修缮阶段。避免只因照片漂亮而混入邻殿。
2. 核查单张照片许可，记录作者、出处、许可链接及所有改动。可访问、无水印、搜索可见均不等于可再分发。
3. 保留原始字节及哈希；生成缩略、展示、高清三个尺寸，默认阅读不加载原片。摄影分辨率和画面清晰度分别判断，禁止用生成式增细伪造证据。
4. `catalog.js` 只配置阅读标题、观察任务、限制和本建筑讲解步骤。`gallery.js` 复用交互；模型用 `architecture:chapter` 通知章节，用 `architecture:photo-model` 响应回看请求。
5. 导入图片需先准备本地文件和 Commons `imageinfo` 元数据，使用含 Pillow 的 Python 执行 `tools/prepare.py <来源目录>`。每条元数据须给出已审阅的建筑 ID、文件名与本地原片路径；作者默认取 Commons Artist（仅纯文本）。`--merge` 可保留既有图录，仅导入新批次。工具在生成前比对来源 SHA1，保留原片 ICC 配置（如有）；Canon 的 JPEG/MPO 以主画面生成展示图，原始字节不变。确认后以 `--upload` 使用环境变量中的既有 R2 凭据；不把凭据放进 JSON、前端或日志。
6. 分别验收 bucket 读回、公开 HTTP 与浏览器图片解码。CDN 访问受阻时保留明确状态和本地备用，不能只看上传命令成功。
7. 桌面与窄屏检查完整画面、最大放大后滚动、切图、Esc、焦点返回、模型回看和图片失败；软件通过不升级模型真实性结论。

## 其他卷接入清单

新卷与旧卷更新均按 [制作规范](../PRODUCTION_GUIDE.md#13-多角度实景图录作为展卷的常规组成) 执行；模型修正与图录共同规划，分别记录证据。以下是接入步骤，不表示其他十一卷已完成配图。

| 位置 | 本卷需要配置或适配的内容 |
| --- | --- |
| 本卷资料与更新记录 | 主建筑/阶段、模型修正目标、照片覆盖矩阵、未取得的视角、只供研究的参考与允许展示的素材 |
| `photos/assets.json` | 经工具导入的本卷照片ID、原作/作者/日期/许可、原始哈希/像素、各尺寸URL；不手填虚构上传结果 |
| `photos/catalog.js` | 增加本卷键；每图配置 `id/title/tag/look/limit/angle/chapter/modelLabel`，必要时加本卷已有的 `node` |
| 本卷HTML与app | 加图录容器和入口，调用 `mountPhotoGallery(host, buildingId)`；实现下述事件，不改原卷地址与合集关系 |
| 取图、存储与备用 | 用本卷ID和来源元数据执行 `prepare.py --merge`；在既有授权范围上传后读回校验；保证各尺寸备用文件随页面交付 |
| 测试与复放 | 扩展图录测试中的建筑/章节/节点表与来源适用范围，适配固定窗口预览的建筑路由，另存本轮日志、截图与源码校验 |

联动约定：

- `chapter` 是本卷 `CHAPTERS` 的**零基索引**，不是界面显示的“06”等序号；`node` 取本卷 `NODES` 中存在的ID。照片ID带本建筑前缀，不沿用别卷的ID或索引。
- 模型切换步骤后发出 `architecture:chapter`，`detail` 为 `{building, chapter}`；图录据此选择相关照片，同一步骤仍保留当前选图。
- 图录回看按钮发出 `architecture:photo-model`，`detail` 为 `{building, chapter, node}`，其中 `node` 可省略。接收方先核对建筑ID，再切换本卷步骤；如有有效节点，调用本卷已有的节点切换逻辑，不能只改变下拉框文字。
- 迁移时核对当前卷的视图与状态模型，不假设所有查看器都有相同的 `setChapter`、图层或节点事件。几何数据与纹样依据仍由本卷重新建立。
- 当前 `catalog.test.js` 的章节/节点导入和 `preview.html` 的建筑路由只覆盖太和殿、太庙；新增卷必须扩展这些适配，不能因为预览默认回到太和殿就误记为新卷通过。

接入验收包括：逐张高清解码、横向与纵向照片、最大放大后滚动、前后按钮与端点、方向键/Esc/焦点返回、多行缩略图、对应模型步骤与实际节点、同一步骤下选图保留、图录失败时模型可读、实际窄屏尺寸与无横向溢出。存储、公开访问和页面解码分开报告；同一来源站限流按其要求重试，证据不全时保持缺口。

## 第二轮范围与记录

太和殿有中轴正面、东南、西南、西北、北侧后檐、转角仰视、柱头斗科、角脊脊兽、梁面彩画、藻井与殿内空间。方向标签取自原作者图名或说明。太庙前殿有两组正面、两组斜向、丹陛仰视、匾额近观与内景；**纯侧面、背面尚无身份与许可均合适的图，不以中殿或后殿补位**。未知罗盘方位只写“斜向”。

太庙2023年图保留7732×5167像素及 Adobe RGB ICC；没有把 Adobe RGB 像素丢掉配置后当作 sRGB 展示。其余照片按原有色彩配置处理，不做生成式增细或改色。

`records/01-source/` 保存首批四图的配置与组件源码；`02-selection.json` 保存选用、排除和缺口说明。`02-upload-batch-a.json` 与 `02-upload-batch-b.json` 对应新增6张、8张两批读回校验，`02-assets.json` 保存完整交付图像校验清单，`02-tests.txt` 和 `02-browser.json` 对应本轮测试。旧截图和日志不覆盖；新截图使用 `02-` 前缀。

来源站限流曾返回 Retry-After:600；按要求等待后降速获取原片。公开 R2 域名受阻与来源站限流是不同问题，前者用静态备用图保证阅读，后者按来源要求重试，不把失败下载记为成功。

复放窗口给文档、脚本明确版本；改动静态模块后需检查实际 script src 与局部节点选择，避免缓存旧脚本使联动验收失真。当前脚本版本为 `photo-atlas-02`。
