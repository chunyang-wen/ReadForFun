# 中国旅行图志城市制作指南

最后整理：2026-10-17。以成都范例为基础，供后续城市的选题、查证、配图、交互实现与交付使用。用户的新要求优先；根目录 [AGENTS.md](../AGENTS.md) 规定图片、音频等媒体统一存放 Cloudflare R2。

本合集面向中文大众和亲子读者，以**吃、玩、人文**认识地方。阅读重点是地方文化与旅行观察，帮助读者理解“这里有什么、为什么有意思、到了当地可以看什么”。首版不以实时价格、餐馆排名、预算或按天行程为目标。

后续通用经验继续补入本文件；[README.md](README.md) 记录实际实现与运行方式，[媒体存储规范](../MEDIA.md) 记录仓库级 R2 流程。每座城市的资料与未决问题跟随该城市保存，避免把个别城市的事实推广成全国结论。

## 0 按省逐个覆盖：2026-10-17 用户确定的长期范围

本项目的目标是按省级地区逐个制作，而不是每省做少数样章就结束。每个省级目录需要向下覆盖有代表性的城市、自治州或县域，以及具体景点、历史人物、诗文、饮食与技艺。代表性选题应尽量详细，并先列清范围，再逐项完成。

- **省级目录**：列清地级行政区及其代表性城市、县域和主题，区分已可阅读的内容与后续选题。城市、自治州、县级市、景点不能混成同一种层级。
- **城市或地区专题**：有独立入口、地方主线、区县目录、吃／玩／人文三类正文，以及适合该地方的人物、作品或技艺。不能只有城市简介或一个筛选后的空壳。
- **详细篇目**：有原创解释与实际观察内容，必要时加入分节正文、历史阶段、人物—作品—地方关系；不能靠增加卡片数量或相同模板段落代替详细制作。
- **验收**：逐项核对已列代表性清单、来源、R2 图片、手机阅读、直接链接与跨地区隔离。待补条目、目录卡、样章不算已经完成；选题尚未穷尽时不得称全省完成。
- **顺序**：当前先展开云南，先细做昆明，再按省内目录推进其它城市和地区。云南尚未完成时不以少量概览宣告收尾。四川原有成都只是省内的一部分，之后必须补其它代表性目的地。
- **重庆**：作为独立的省级直辖市专题，与四川并列规划，不塞入四川城市目录。其城区、区县和景点仍需逐层展开；当前尚无正文，不能伪装成已制作城市。
- **资料存储**：研究、测试、截图、原图、字体原文件等放在 `.work/` 等明确忽略的目录。Git 只保留展示所需代码、正文、实际展示的覆盖目录、数据、提示词和许可；图片、音频仍在 R2。

当前云南省内目录为 16 个州、市，四个地区已有选篇，昆明已展开十篇专题（仍列有后续代表性主题）。这些是实际覆盖量，不是“云南已经做全”的证明。

## 1 从成都讨论中确定的产品要求

| 方面 | 沿用的要求 | 制作时的含义 |
| --- | --- | --- |
| 读者 | 中文大众与亲子兼顾 | 正文自然易懂；孩子的观察任务按需展开，不把整篇写成问答练习 |
| 内容 | 吃、玩、人文并重 | 地方食物、自然与城市空间、诗词人物和日常文化都要进入选题 |
| 视觉 | 山水旅行手札与现代地图指南结合 | 统一淡彩插画、暖白纸底、墨色文字、青绿与赭色；搜索、筛选保持清楚 |
| 探索 | 地图与目的地列表联动 | 不熟悉地理的人也能搜索城市、主题、人物与诗句 |
| 阅读 | 城市专题与连续章节 | 章节用于定位，单篇有独立链接；同一篇可跨类出现 |
| 图片 | 统一插画图志 | 插画标注“艺术化呈现”，不能充当实景照片或精确复原证据 |
| 教育 | 数字解释层级，故事连接地方 | 明确区划口径，让诗词、人物、遗迹和当代生活互相联系 |
| 存储 | 媒体放 R2，网页引用云端地址 | Git 保存代码、文字、GeoJSON、字体子集、许可、提示词与素材清单 |

成都目前有九篇独立故事、三个人物条目、三首诗词条目（含节选）。这些数量是范例现状，不是每座城市必须填满的配额。选择最能解释地方特点的内容，不能为凑数编造人物关联、诗作或历史细节。

## 2 怎样组织一座城市的内容

### 2.1 先写一条城市主线

用一句话回答“读者为什么从这座城开始”。成都以“一盏茶里的生活节奏”串起食物、公园与文化。新城市应从自己的地理、历史或生活特点出发，不套用成都的茶馆、竹椅和慢生活叙事。

先列出候选主题、所属区县、与主线的关系及资料入口，再确定文章。每个主题至少回答一个读者可以带走的问题。

| 章节 | 选题范围 | 要解释的问题 | 成都示例 |
| --- | --- | --- | --- |
| 吃 | 代表食物、地方饮食与器物 | 怎么看、怎么尝、与地方生活有什么关系 | 担担面、盖碗与茶馆 |
| 玩 | 山水、景点、公园、街巷与观察活动 | 到这里可以发现什么，而不只是在哪里拍照 | 城市公园、都江堰 |
| 人文 | 诗词、文人、历史人物、技艺、戏曲与生活 | 谁与这里有关，留下了什么，今天如何理解 | 杜甫、薛涛、诸葛亮、川剧、蜀锦 |

标签允许交叉：茶馆可以属于吃与人文，诗人纪念地可以属于玩与人文。一个故事保留一个稳定 ID，在不同入口复用；故事总数按 ID 去重，不能把跨类展示次数当成内容数量。

### 2.2 单篇采用共同骨架

文章依次包括：主题插画、短导语、可观察的小细节、地方故事、当地观察提示、亲子折叠问题、相关篇目和来源。诗词人物主题在适当位置加入原文、白话解释、人物背景及地点关系。

短导语先说明这个主题为何值得了解；正文讲具体器物、动作、景物和人的经历。观察提示应该能在现场执行，例如“辨认盖、碗、托”或“找碑刻上的年代”。涉及热水、临水或文物时，把必要提醒放在对应活动旁边。

阅读时长依据实际文字量估算。区县信息只在核实后填写；属于全市饮食或生活氛围的文章，可以暂不绑定区县，不能为了通过筛选把它随意放进某一区。

### 2.3 人文必须形成关系链

基本关系是：**人物 → 作品或事迹 → 地方 → 今天可理解或观察的内容**。作者籍贯、曾到访、流寓创作、诗中提及和后世纪念不是同一种关系。

| 联系类型 | 页面应如何说明 | 容易犯的错误 |
| --- | --- | --- |
| 生活或创作地 | 说明人物与当地生活、创作的联系 | 把所有相关作品都断言为在这个景点写成 |
| 作品中的地名 | 解释它是眼前景物、远景、回忆还是想象 | 把诗中每个地名都放成作者当时的游览点 |
| 后世纪念地 | 交代纪念对象与后世建造、修葺的关系 | 把纪念馆或现存园林说成原居所原貌 |
| 历史人物与文学形象 | 分开讲史实、诗文表达和民间传说 | 用小说或传说直接证明历史事件 |

成都例子：《绝句》中的西岭与东吴不能都绑定成草堂旁的游览点；望江楼的薛涛纪念空间不能当成唐代原居所复原；武侯祠可以同时讲诸葛亮、杜甫《蜀相》和后世纪念，但三个时代应分开说明。

诗词条目应有题名、作者、时代、可靠原文、全文或节选标识、原创白话解释、地方关系、相关故事与来源。核对异文和作者归属；现代作品还要核对使用许可。内部已有唐诗、宋词讲解时可以深链复用，原文和地方关系仍需查证。

## 3 查证来源与地理数字

### 3.1 让每个重要说法有依据

优先核对政府统计、博物馆与纪念馆、非遗机构、原始文献、地方志和可靠研究。搜索摘要用于找到材料，正文证据用于决定可以写什么。保存具体页面或条目，不用机构首页代替文章来源。

每条资料记录机构、标题、链接、支持的说法、资料日期或数据时点、核对日期；必要时保存原文节录和 R2 备份地址。仅能确认主题氛围的资料，不能支持精确年代、建筑形制或设备构造。

确定的史实、资料存在异文的判断、传说与艺术化想象应分别表达。找不到可靠依据时，缩小说法或暂缓该选题，不用生成图补充历史证据。

### 3.2 数字讲清楚层级与口径

统计卡随全国、省级地区和城市选择切换。行政区划总量与“图志已收录多少城市、故事”分开显示，搜索结果数量也不等于真实区划总数。

- 全国使用“省级行政区”，并解释省、自治区、直辖市、特别行政区的分类。
- 省级展示地级行政区数量及其中的地级市数量；自治州、地区、盟不能统称为城市。
- 城市使用“县级行政区”，并拆分区、县级市、县及当地适用的其它类型。
- “其中”是包含关系，不能再次相加；直辖市的地级栏不适用，也不能误写为“没有城市”。
- 功能区、开发区不能未经核实作为独立县级单位重复计数。香港、澳门和台湾地区的地方制度按各自资料解释，不强行套用统一的省市县层级。
- 数字旁直接显示统计时点；来源与详细口径可展开。资料发布日期、数据时点、核对日期分别保存。未知值保留为空并说明，不能变成零。

成都使用的示范：2024 年底统计表中，四川有 21 个地级行政区，其中 18 个地级市、3 个自治州；成都市区县目录为 20 个县级行政区，分成 12 区、5 个县级市、3 县。后者当前记录的是地图数据核对日期，不能改写成来源未提供的“统计生效年份”。新城市应重新查证，不能照搬这些数字。

教育数字不必越多越好。优先选择能帮助理解地方的内容，例如区县类别、本文收录的人物与作品数量；面积、海拔、人口或遗产数量只有在来源、时点和统计范围明确时再加入。

### 3.3 地图与统计分别核验

地图使用真实地理数据，AI 插画只承担氛围与装饰。保存 GeoJSON 来源与获取日期；省级分类、区县代码和名单另与统计资料核对。地图的 `childrenNum` 未必都代表“市”，不能直接用于市级总数。

当前全国统计采用《全国行政区划（2024 年底）》历史快照，不能称为实时数据。以后更新数据时，检查各省合计、区县分类及适用范围，避免把不同年份的数字混成同一张表。

## 4 视觉样例与图片制作

### 4.1 先做完整路径，再扩展内容

成都第一轮用六张样例讨论完整体验：全国地图与侧栏、选中城市预览、城市首页、吃的章节、茶馆详情、手机地图与阅读对照。新增城市可以复用这套讨论方式；全国入口无需每次重画，重点验证新城市的主线、插画和阅读页面。

先审构图、文字层级、图片风格和操作路径，再大量生成正文素材。概念图出现的额外导航或功能，不自动成为实现要求；对应页面应明确哪些已实现、哪些仍只是样例。

### 4.2 图片与文字各司其职

默认使用内置 imagegen。页面概念图采用 `ui-mockup`，正文插画采用 `illustration-story` 等合适类型。提示词保留用途、主体、风格、构图、关键地方特征及禁止项；每轮只针对明确问题调整，并保存最终提示词。

生成结果逐张检查地方识别、器物特征、人物衣饰、文字错误和跨图风格。示意图不能被用来支持建筑、人物容貌或工程精度。页面统一标注艺术化呈现，需要时再补充“非实景或技术复原”。

正式文字、地图、导航与按钮独立实现。生成图中的中文和地图可能有误，不把整张 UI 截图作为真实页面。必要的小图解可以用网页原生绘图实现，文字和无障碍说明保持独立。

### 4.3 从成都素材表得到的经验

六格插画表和人文三联画便于统一风格，但面板顺序、数量和实际长宽比必须记录。先检查源图尺寸，再计算 CSS 显示方式；不能靠拉伸整张图片适配每个容器。不同屏幕用裁切保留主体，并核对碗、建筑和人物是否被切断。

当前 `scene` 与 CSS 素材表位置相连，并有成都专属的分支。新城市不能继续盲目递增编号：少量独立主题优先使用可独立更新的图片 URL；确实复用素材表时，为每个主题明确素材表、面板位置和比例。

字体沿用文楷标题、宋体正文、黑体导航的层次。新增内容后更新字体子集，检查新地名、人物名、诗句与生僻字的回退。核对真实字体格式和体积，避免字体服务返回完整字体后误当成小型子集。字体许可留在 Git。

## 5 媒体先上 R2 再接入网页

### 5.1 必须遵守的存储流程

1. 生成或取得素材，保存到被 Git 忽略的本地工作目录；原始生成文件可以另外保留。
2. 核对内容、版权与用途，计算文件 SHA-256，使用含内容哈希的 R2 对象键。
3. 上传后通过 R2 API 读回并比对摘要；写入根目录 `media-assets.json`，保留 URL、对象键、字节数、类型及验证结果。
4. 网页、样例页、封面和文档使用对应 CDN 地址；不引用仅存在于 Codex 生成目录的文件。
5. 在真实页面中验证公开图片加载和 `decode()`；本地图片不是云端地址失效时的隐含依赖。
6. 提交代码、文字、清单、提示词、许可与必要数据，图片和音频保持未跟踪且被忽略。

不能先把 PNG 提交再计划以后上传。成都曾在一个未推送提交中混入旅行与建筑媒体，后迁移了 218 个图片对象、约 80 MB，并替换该提交。这个数字是当次仓库迁移的合计，不是成都单城的图片体积。后补一个“删除图片”的提交并不会移除祖先提交里的大文件；需要处理历史时先核对提交是否已推送、保留其它工作，并按用户授权选择操作。

R2 对象校验、公开 CDN HTTP 响应、浏览器图片解码是不同检查。本次曾出现命令行公开请求 403、浏览器解码成功的情况：不能据单一客户端判断所有用户可用，也不能用已上传代替页面可用。保留测试条件和实际结果，必要时定位失败层级。

### 5.2 复用上传脚本时使用临时索引

现有上传脚本枚举“暂存区中新加或修改的媒体”。为了不把图片加入真实提交，可以用独立 Git 索引提供待上传名单。以下在仓库根目录执行，把示例路径换成实际文件；本地 R2 配置沿用现有 `.envrc`，不要输出或提交密钥。

```sh
# 临时索引只用于列出这批媒体，不影响真实暂存区。
task_media_index="$(mktemp -d)/index"
GIT_INDEX_FILE="$task_media_index" git read-tree HEAD
GIT_INDEX_FILE="$task_media_index" git add -f -- travel-in-china/assets/NEW_CITY_IMAGE.png
GIT_INDEX_FILE="$task_media_index" uv run --python python3 --with 'boto3>=1.40' python scripts/publish_staged_media.py

# 核对上传清单后，更新已有文件中的具体图片路径引用。
python3 scripts/rewrite_media_references.py

# 提交前，对真实暂存区执行媒体检查。
python3 scripts/check_media_policy.py
```

脚本只自动替换已纳入 Git 索引的页面、样式和文档中的具体相对路径；新建但未加入索引的文本文件、动态拼接路径、测试输出路径需要人工检查或显式使用清单 URL。通配上传后确认清单仍合并保留旧记录；相同对象键内容不一致时不能覆盖掩盖问题。确认完成后可删除本次新建的临时索引目录。

上传工具当前按有限的媒体扩展名识别；采用新格式前检查脚本支持，并添加对应类型、内容类型和验证。忽略规则和政策检查脚本只是防线，不能替代查看最终差异。

## 6 页面交互与新增城市的实现边界

### 6.1 沿用的浏览行为

桌面地图与侧栏并列。选择省份后更新城市范围；选择城市后先显示预览，再通过“探索这里”进入。未收录地区仍可了解数字和区划知识，并有返回入口。

手机默认目的地列表，可切换地图；选中预览位于地图下方的文档流，不用大面板盖住地图。搜索、主题筛选、区县选择和诗词人物切换都需要清楚的选中状态与空状态。

返回时恢复实际离开位置、地图选择与筛选；文章与城市支持直接链接。地图按钮支持键盘，微小地区提供文字选择入口。保持正文约 18px、合理行距、可见键盘焦点和减少动态效果支持。

### 6.2 第二座城市不能只复制成都页面

当前已用 `destinations.js` 统一目录支持成都城市图志与云南省级图志。地图预览、搜索、通用路由、阅读页和文化关系按目的地配置读取，原有成都链接保留。成都数字卡仍有城市专属实现；新增其它城市时，需要继续扩展城市统计卡，不能把它直接套用到新城市。

云南是省级专题，使用 `region` 参数按地级行政区筛选，清楚区分地级市与自治州；成都使用 `county` 参数按县级行政区筛选。省级专题与城市专题共用阅读组件，但层级、统计、目录和主线由各自配置定义。云南的少量插画显式记录素材表 URL、面板位置、尺寸比例；不继承成都场景编号。人物、作品和文章关系均从当前目的地查找。

新增目的地至少提供稳定 ID、名称与拼音、省级代码、类型、主线与导语、封面 R2 URL、文章与文化数据、对应层级的区划名单及数字来源。城市级与省级内容保持独立，不为省级专题虚构县级城市总表。研究、测试、原始字体与本地媒体放到 `.work/` 等已忽略目录。

将 `#/城市ID`、`#/城市ID/文章ID` 作为通用路由形式；城市内保留章节和区县参数。人物、诗词与文章关系都带城市上下文，避免不同城市的同名条目或 ID 冲突。县级代码保持字符串，缺少可靠定位时不自动补全。

内容数量、匹配城市、相关篇目、覆盖范围和空状态必须由当前城市数据计算。城市介绍图不可继续被统一替换为茶馆；新城市筛选不能混入成都诗词；旧城市直接链接和返回位置需要回归验证。开始实现前阅读对应文件，更新这份指南中的实现现状。

## 7 制作顺序与验收

| 顺序 | 本阶段产物 | 完成条件 |
| --- | --- | --- |
| 1 选题 | 城市主线、三类主题与区县分布 | 内容具有地方差异，范围适合一次完整交付 |
| 2 查证 | 事实表、作品与人物关系、区划记录 | 每个重要说法有具体来源；时间和口径清楚 |
| 3 视觉讨论 | 城市首页、章节、详情与手机样例 | 图片风格一致，真实交互路径清楚 |
| 4 内容制作 | 正文、诗词解释、人物与亲子观察 | 文字独立可读，没有无据的地理或历史关联 |
| 5 素材接入 | R2 地址、摘要、许可与提示词 | 先上传验证，再写网页引用；媒体不进 Git |
| 6 实现 | 城市目录、页面、地图联动与筛选 | 新旧城市隔离，直接链接可用 |
| 7 验收 | 数据检查、浏览器结果与截图 | 数据关系、公开图片、手机和返回行为均实际检查 |
| 8 交付 | 状态、已完成范围、未决问题与入口 | 不把概念图、推定或本地实现说成正式发布 |

数据检查应覆盖 ID 唯一性、所有关系可解析、来源齐全、区县代码与名单一致、同口径合计正确，以及收录数量去重。现有成都检查可作为入口：

```sh
node --test travel-in-china/tests/knowledge.test.mjs
node travel-in-china/tests/browser.mjs
```

浏览器测试需要按本机情况配置 Playwright、Chromium 与静态服务器，具体方式见 [README.md](README.md)。新增城市后，增加针对该城市与跨城隔离的断言，不能沿用成都计数冒充新城覆盖。

人工及浏览器至少检查：全国与省份切换、城市二次确认、城市与文章直达、搜索人物和诗句、无结果、未收录区县、诗词人物切换、实际离开位置恢复、键盘、小屏无横向溢出、减少动态效果、地图失败与重试。远程图片在无本地图片缓存的条件下检查；图片尺寸、裁切与字体还需要视觉复核。

测试导航时，在自动滚动到点击目标之后记录离开位置。成都人文章节加长后，测试框架会先滚动到文章链接；若仍拿滚动之前的位置比较，会误报返回恢复失败。

交付记录分别写清静态数据检查、浏览器操作、图片解码和视觉检查的实际范围。文档小改不需要重复模型或浏览器全套测试，但新增交互、媒体地址或数据关系必须检查对应路径。提交前运行媒体政策检查、核对暂存差异与工作区状态；是否提交、推送或发布沿用用户的明确授权。
